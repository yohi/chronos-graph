# AIエージェント向け自動セットアップ（Agent Setup Protocol）

> [!CAUTION]
> **AIエージェントへの強制命令 (CRITICAL):**
> あなたが AI エージェント（Claude Code / Gemini CLI / Cursor 等）である場合、いかなる副作用（インストール、ファイルの作成・修正、コマンド実行）を伴うアクションを開始する前に、必ず以下の **Agent Setup Protocol** を遵守してください。
> **たとえ `.env` や設定ファイルが既に存在していても、それが本プロトコル（ask ツールによる明示的承認）を経て作成された正当なものであるか確証が持てない場合は、決してスキップせず、必ず Phase 1 から再開してください。** 自己完結的な現状判断による「スキップの宣言」は、プロトコル違反とみなされます。

> [!IMPORTANT]
> **🚨 ユーザー確認ツール（Askツール等）の使用強制 (STRICT ASK CONSTRAINT):**
> あなた（AIエージェント）が各フェーズの **`BLOCKING STEP`** を実行する際は、**絶対にチャットテキスト上の対話だけで自己完結して進めてはいけません。**
> 「すでに完了しているように見えます」という報告や「スキップします」という合意形成であっても、それがセットアップの根幹に関わる判断であるなら、必ず `ask_question` 等のツールを明示的に呼び出し、ユーザーがUI上で明示的に合意するプロセスを確実に踏んでください。
> ツール経由での明示的な承認が得られるまで、次のステップへ処理を進めることは厳格に禁止されます。

<agent-rules>

#### 💻 ターゲット環境（OS）の自動適応ルール（OS Adaptation Rule）
1. **OS の能動的判定**:
   ファイルやスクリプトを作成する前に、必ず `uname` や環境変数（例：`$OSTYPE`）等を確認し、現在の実行環境（Linux, macOS, Windows）を特定してください。
2. **適切な拡張子と構文の採用**:
   * **Linux / macOS**: 実行可能なシェルスクリプト（`.sh`）を作成し、必ず `chmod +x <ファイル名>` を実行してください。
   * **Windows**: バッチスクリプト（`.cmd`）または PowerShell（`.ps1`）を作成してください。

#### 🔐 機密情報の分離収集ルール（Sensitive Information Handling Rule）
1. **非機密情報のツール収集徹底と省略の厳格禁止**: 
   セットアップに必要な一般設定（ストレージの種類、モデル名、パス等）など、機密情報以外のすべての設定項目は、**「デフォルト値があるから」「前項の選択肢から推測できるから」といった理由でAIエージェントが勝手に自己完結して入力を省略（スキップ）することを厳格に禁止します。** 必ず `ask_question` 等の入力ツールを用いて明示的にすべての選択肢・設定項目をユーザーに提示し、入力を求めてください。
2. **入力反映済み .env の提示と機密情報の直接入力要求**:
   ユーザーがツールで入力した一般設定の内容を反映した `.env` ファイル（またはその内容のテンプレート）を作成・提示してください。その際、APIキーやパスワード等の機密情報部分のみを空欄や `YOUR_API_KEY_HERE` などのプレースホルダーにした状態にし、ユーザーに対して「この `.env` に機密情報を直接手動で入力してください」と求めてください。ツール（ask_question等）やチャット上での機密情報の直接入力は絶対に求めてはいけません。
3. **不要な設定値のコメントアウト徹底と削除の厳禁**:
   `.env` 作成時は、必ず `.env.example` をそのままコピーして作成してください。**選択されなかった機能のブロックや不要な設定項目であっても、ファイルから削除（間引き）することは厳格に禁止します。不要なものは削除する代わりに、必ずすべてコメントアウト（`#`を先頭に付与）してファイル内に残し、テンプレートの全体構造を100%維持してください。**
4. **不要なLLM評価設定の除外（長期記憶MCPセットアップ時）**:
   長期記憶MCP（ケースA）のセットアップを行う場合は、LLM評価器（`CHRONOS_EVALUATOR_*` や `MCP_GATEWAY_*`）の設定は一切不要です。これらは `.env` 内でコメントアウトされたままにするか、設定を行わないでください。

</agent-rules>

## 🟦 Setup Phases

### Phase 1: 目的の確定と実行モードの選択 (BLOCKING STEP)
いかなる変更を伴うツールを呼び出す前に、必ずユーザーに以下の質問を提示し、セットアップ目的および **実行モード** を確定させてください。

1. **セットアップ対象の選択**:
   * `1. 長期記憶MCP`（MCPサーバーとしての起動・登録）
   * `2. 安全評価Hook`（ツール実行前保護フックの登録）
2. **実行モード of 選択**:
   * `本番モード`（実際に環境構築・ファイルの変更を行う）
   * `デバッグモード（Dry-run）`（ファイルを一切変更せず、本番で生成されるべき設定内容や実行コマンドのシミュレーションと解説のみを行う）
   * **判定条件**: 
     - ローカルの `@README.md` などの参照から実行している場合は、必ず本質問で「本番かDry-runか」を確認・選択させてください。
     - `https://raw.githubusercontent.com/...` 等のリモートファイルから直接ロードされている場合は、デフォルトで「本番モード」として進行して構いません。

---

### Phase 2: 詳細設定の確認とロックイン (BLOCKING STEP)

#### 【ケース A】長期記憶MCPの場合
以下の項目を `ask_question` 等を用いて一括でユーザーに提示し、回答を確定させてください。
*(※長期記憶MCPの場合、LLM評価（Evaluator）の設定は一切不要です)*

1. **配置・起動方法 (Source)**:
   * `remote` (🌟推奨: リポジトリをクローンせず `uvx` を用いてオンザフライで起動・実行する)
   * `local` (ローカルにクローン済みの本リポジトリ内で直接実行する)
2. **保存モード (Ingestion Mode)**:
   * `all` (全量保存モード: エージェントのターン終了時に会話ログをバックグラウンドで全量自動保存。**Ingestion Mode が all の場合に限り、Phase 6 でクライアント側への Stop event hook の追加設定が必要です**)
   * `selective` (自律判断保存モード: AIが重要と判断した情報のみを `memory_save` ツール経由で保存。**クライアント側へのフック設定は不要です**)
3. **ストレージ (Storage Backend)**:
   * `sqlite` (🌟推奨: ゼロ設定かつ軽量に動作し、外部データベースコンテナ不要)
   * `postgres` (本番用: pgvector が必要)
   * `supabase` (本番用: クラウドベースの Supabase Data API を経由)
4. **PostgreSQL ベクトル検索前提確認 (PostgreSQL選択時のみ)**:
   * `確認した` (pgvector拡張が有効であることを確認します)
   * `該当なし` (PostgreSQLを選択していない場合)
5. **Neo4j接続（グラフ関係性機能）**:
   * `有効` (SQLiteは内部グラフ、Postgresは外部Neo4jを使用)
   * `無効` (🌟推奨: 高速かつシンプルな軽量構成)
6. **キャッシュ**:
   * `inmemory` (🌟推奨: プロセス内メモリで管理)
   * `redis` (本番用: 外部の Redis キャッシュサーバーを使用)
7. **埋め込みベクトルモデル**:
   * `cl-nagoya/ruri-v3-310m` (🌟推奨: 日本語に優れ、ローカルで動作する標準モデル)
   * `OpenAI` (OpenAI の高品質な Embedding API を利用)
8. **OpenAIのモデルとAPIキーの確認 (EmbeddingがOpenAIのときのみ)**:
   * `text-embedding-3-small` / `text-embedding-3-large` / `text-embedding-ada-002` からモデル名を確認。
   * APIキーは `.env` への直接手動入力が必要となる点を確認（機密情報のためツールでは収集しません）。

#### 【ケース B】安全評価Hookの場合
以下の項目を `ask_question` 等を用いて一括でユーザーに提示し、回答を確定させてください。

1. **安全評価を行うLLMモデル**:
   * 使用する LLM モデル（例: `anthropic/claude-3-5-haiku-20241022` 等）を入力・確認。
2. **APIキーの確認**:
   * `CHRONOS_EVALUATOR_API_KEY` を `.env` に設定することへの確認（機密情報のためツールでは収集しません）。

---

### Phase 3: パラメータの収集と .env ファイルの生成 (BLOCKING STEP)
上記の回答結果に基づいて、**機密情報に該当しない追加のパラメータ** の入力を `ask_question` 等の入力ツールを用いてユーザーに求めてください。

* **PostgreSQL選択時**: `ホスト名`、`ポート番号`、`データベース名`、`ユーザー名` の入力を求めます。（パスワードは機密情報のため収集しません）
* **Neo4j接続（グラフ有効時）**: `Neo4j URI`、`ユーザー名` の入力を求めます。（パスワードは機密情報のため収集しません）
* **Redis選択時**: `Redis 接続URL`（例: `redis://localhost:6379/0`。パスワード等を含むURLの場合は、パスワード部分をプレースホルダーとして入力）の入力を求めます。

#### ファイルの作成と機密情報の入力
1. **.envのコピー作成**: `.env.example` をコピーして `.env` を作成します。
2. **不要項目のコメントアウト徹底と削除禁止**: 
   選択されなかった機能ブロックや設定項目について、ファイルから一部でも削除してはいけません。**不要な値やブロックは、削除する代わりに必ずすべてコメントアウト（先頭に `#` を付与）してファイル内に残してください。** 特に、長期記憶MCP（ケースA）の場合は、LLM評価に関連する `CHRONOS_EVALUATOR_*` などの設定はすべて削除せず、コメントアウトした状態のままにしてください。
3. **機密情報の直接入力要求**: 
   収集した設定値を `.env` に反映させつつ、パスワードやAPIキーなどの機密情報箇所は空欄またはプレースホルダーにした状態で提示します。ユーザーに対して「`.env` ファイルに機密情報を直接手動で入力してください」と求め、ユーザーから「入力が完了した」という報告を受けるまで待機してください。

ユーザーからの完了報告後、ローカルリポジトリでセットアップする場合は以下の接続疎通確認コマンド等を実行し、検証ログを表示します。
* `uv run python scripts/check_connectivity.py`（または remote 構成時は同等の `uvx` コマンド）

### Phase 5: 対象AIエージェントの選択 (BLOCKING STEP)
接続テストが完了したら、必ず `ask_question` 等のツールを使用して、複数選択可能な形式で以下の対象エージェントを提示し、ユーザーに選択させてください。

* `[ ] ClaudeCode`
* `[ ] Codex`
* `[ ] AntigravityCL`
* `[ ] OpenCode`
* `[ ] CursorCLI`

### Phase 6: セットアップ実行 (設定追加・スクリプト配置)
選択されたエージェント向けの設定追加やスクリプトの配置を行います。

1. **長期記憶MCPのフック設定（Ingestion Mode が all の時のみ）**:
   * 長期記憶MCPのセットアップ（ケースA）において、保存モードが `all`（全量保存）の時のみ、クライアント側ターン終了フック（Stop event hook）を設定します。`selective` モードの場合はフック設定は不要です。
2. **フックスクリプトの作成と配置（ClaudeCode, Codex, AntigravityCL, CursorCLI 用）**:
   * 対象OSに応じたフックスクリプト（Linux/macOSなら `.sh`、Windowsなら `.cmd` 等）を作成・配置します。
   * フックスクリプトを作成した場合は、実行権限（`chmod +x` 等）を付与し、`view_file` や `ls -la` などのコマンドで実在を確認し、ログに出力して証明してください。
3. **OpenCode の PluginHook 設定（OpenCode 用）**:
   * **OpenCode については、スクリプト（.sh / .cmd 等）を作成するのではなく、Github Packages から NPMパッケージをインストールし、グローバル設定ファイル（~/.config/opencode/opencode.json または ~/.config/opencode/opencode.jsonc）の `plugin` 配列に追加する形で PluginHook を有効化します。** スクリプトファイルを作成・配置してはいけません。
   * **GitHub Packages からのインストール手順**:
     - ユーザーに対して、GitHub Packages (`https://github.com/yohi/chronos-graph/pkgs/npm/opencode-plugin-chronos-gate`) から取得するために、`.npmrc` 等に以下のレジストリ設定を追加するように求めてください。
       ```text
       @yohi:registry=https://npm.pkg.github.com
       ```
     - インストールおよび有効化手順として、`~/.config/opencode/opencode.json` (または `~/.config/opencode/opencode.jsonc`) の `"plugin"` 配列に以下のようにパッケージ名を追加するよう案内してください。
       ```json
       {
         "plugin": [
           "@yohi/opencode-plugin-chronos-gate"
         ]
       }
       ```
     - **Gateway自動起動の仕組み**:
       - プラグインには `session.created`（対話開始時）のフックが組み込まれています。OpenCode 起動時に Gateway サーバーが未起動（ポート 9100 が応答しない）の場合、バックグラウンドで自動的に `chronos-mcp-gateway` サーバーを起動します。そのため、ユーザーが手動で Gateway を起動しておく必要はありません。
     - > [!IMPORTANT]
     - > **AIエージェントへの注意事項（ハルシネーション防止）**:
     - > 設定ファイルの `"plugin"` 配列に登録されたパッケージは、**OpenCode 起動時に Bun により自動フェッチされ、専用キャッシュ（`~/.cache/opencode/node_modules/`）にダウンロード・ロードされます。**
     - > したがって、セットアップ直後にカレントディレクトリの `node_modules` 内にパッケージが存在しないことや、ローカルの `plugins/chronos-gate.js` と不一致があること等をエラー（または未インストール）と誤認してはいけません。手動インストールや手動配置のコマンドを追加で実行するなどの無駄な処理を行わないでください。
4. **ポリシーファイル等の配置**:
   * ポリシーファイル（`intents.yaml`）などの配置指示を正しく行います。

### Phase 7: 動作確認など最終チェック
**このフェーズは「安全評価Hook（ケースB）」のセットアップ時のみ実行してください。長期記憶MCP（ケースA）のセットアップ時は、本動作確認テストはスキップし、Phase 6 の完了をもって終了とします。**

安全評価Hook（ケースB）のセットアップ完了後、必ずフック評価テストコマンドを実行し、正常に許可/拒否（`allow`/`deny`）が判定できることを検証・ログに出力してください。
* テストコマンド例：
  `echo '{"tool_name":"bash","tool_input":{"command":"ls"}}' | chronos-mcp-gateway evaluate --json-io --policy-path "./intents.yaml"`
  *(※環境に応じて `uv run` 等を適切に構成してください)*
